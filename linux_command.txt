

##System and process management

ps aux               --> list all running processes
top / htop           --> monitor CPU, memory, running processes
free -h              --> check memory usage
df -h                --> check disk usage
du -sh <folder>      --> check folder size
kill -9 <pid>        --> force kill a process

systemctl status <service>   --> check service status (e.g. nginx, docker)
systemctl start/stop/restart <service>
journalctl -u <service>      --> view service logs



##Networking (essential for cloud/servers)

ping <host>         --> check connectivity
curl -I <url>       --> check HTTP response headers
netstat -tulnp      --> list open ports and listening services
ss -tulnp           --> modern replacement for netstat

ssh user@host         --> connect to a remote server
scp file user@host:/path   --> copy files over SSH
ip a                  --> check network interfaces/IP


##File & permission management

chmod 755 file        --> change permissions
chown user:group file --> change ownership
ls -la                --> list files with permissions
find / -name "file"   --> search for files
grep -r "text" .      --> search text inside files
tail -f logfile.log   --> live-follow a log file (great for debugging deployed apps)


##Package & environment management

apt update && apt upgrade     --> update packages (Debian/Ubuntu — common on cloud VMs)
apt install <package>
which <command>               --> find path of a command
env                           --> view environment variables
export VAR=value              --> set environment variable (used a lot in cloud configs)

##Docker (since it's on your roadmap)

docker ps                           --> list running containers
docker images                       --> list images
docker build -t name .              --> build image from Dockerfile
docker run -d -p 80:80 name         --> run container
docker logs <container>             --> view container logs
docker exec -it <container> bash    --> shell into a running container


##AWS CLI basics (once you get there)

aws configure                   --> set up credentials
aws s3 ls                       --> list S3 buckets
aws ec2 describe-instances
aws s3 cp file s3://bucket/     --> upload file to S3

##copy file from local storage and run in instance 

scp -i "My-Server.pem" "D:\PEP\summer-pep\aws\aws-file" ubuntu@ec2-ip--.compute-1.amazonaws.com:/home/ubuntu/


What to add depends on how you're serving the files:

If you're using...	Add this rule
Plain HTTP (nginx/apache on port 80)	Type: HTTP, Port: 80, Source: 0.0.0.0/0
HTTPS (SSL-enabled)	Type: HTTPS, Port: 443, Source: 0.0.0.0/0
Node.js dev server (e.g. http-server, Express)	Type: Custom TCP, Port: e.g. 3000 or 8080, Source: 0.0.0.0/0
live-server / VS Code Live Server	Type: Custom TCP, Port: 5500 (or whatever it uses)

##the simplest way to go live is with nginx serving it on port 80 (standard web port, no extra port number needed in the URL).

##Step 1: SSH into your instance

ssh -i "My-Server.pem" ubuntu@ec2-52-1-89-201.compute-1.amazonaws.com

##Step 2: Install nginx

sudo apt update
sudo apt install nginx -y

##Step 3: Copy your files into nginx's web root

sudo rm -rf /var/www/html/*
sudo cp -r ~/aws-file/* /var/www/html/

##Step 4: Start nginx (if not already running)

sudo systemctl start nginx
sudo systemctl enable nginx

Step 5: Open port 80 in your security group
Go back to the Inbound rules you were just looking at → Add rule:

Type: HTTP
Port: 80
Source: 0.0.0.0/0

Click Save rules.

Step 6: Visit your site
Open this in a browser:

http://ec2-ip--.compute-1.amazonaws.com

That's it — your index.html should load, and it'll pull in script.js and style.css automatically since they're in the same folder.
